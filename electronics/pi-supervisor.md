# Pi Supervisor — Orange Pi Zero 2W #1 Onboard

Role: data-logger + trim advisor + telemetry forwarder. NOT flight controller. Robot fights identically with Pi removed.

## Hardware Install
- Board: Orange Pi Zero 2W 1GB, Armbian minimal, overlayfs + readonly root, heatsink + kapton.
- Power: Matek Micro BEC 5V/4A (set 5.1V) from PDB, twisted 20AWG + 470µF cap at Pi header. Separate from MCU/RX 5V rail. Current: 0.6-1.1A typical, 2A peaks on WiFi TX — size for 3A continuous.
- Isolation mount: TPU grommets + 3M VHB + silicone potting on SD slot. Mount at spin center stack, below Rotini. SD: SanDisk High Endurance 32GB, locked RO after boot. Use eMMC if available.
- UART: Pi UART5 (pins 8/10) <-> Rotini UART0 @ 460800 baud, GND common star-point at PDB. 1k series resistors. No flow control. COBS framing, CRC16.
- Kill authority: NONE. Pi cannot arm, cannot clear failsafe, cannot drive PWM.

## Software Services (systemd, all `Nice=10`, non-realtime)
1. `melt-link` (Python/C, 100Hz RX / 50Hz TX): parse MCU telemetry, publish trim packets, forward CRSF LQ/RSSI to log.
2. `melt-blackbox` (50Hz): append-only CSV + MCap to /var/log/melt. Fields: t, rpm, heading_err, vbat, esc_temp, lq, ax,ay,az (±400g), trim_state, hit_flag.
3. `melt-telemetry` : CRSF telemetry passthrough request via MCU (MCU owns RF link — Pi never transmits RC). Sends Vbat/RPM to Pocket via CRSF telemetry frames relayed through Rotini.
4. `melt-wifi` (pit only): hotspot OFF in arena. STA mode to pit AP for download after match. `rfkill block wifi` on arm pin (GPIO reads ARM LED line).

## Functions (Advisory, MCU-Clamped)
- **RPM-hold:** Pi runs slow PI (10Hz) on RPM error → sends ±10% setpoint trim. MCU clamps 1200-3200 RPM hard. Default 2200 RPM if Pi absent.
- **Auto-spinup:** Pi may request `SPINUP_REQ`. MCU only honors if (a) armed via RC, (b) throttle >10%, (c) no failsafe. MCU executes ramp locally. Pi timeout 5s → abort.
- **Hit-detect:** Threshold on H3LIS331DL delta (>80g spike) + RPM drop >15% in 100ms → log marker + brief RPM boost request (+5% for 500ms, MCU-clamped). No steering change.
- **CRSF telemetry:** Vbat, RPM, LQ shown on Pocket. Generated by MCU; Pi values are display-only copies.

## Boot-Time Safety (36s Boot Must Not = Runaway)
- Power-on: MCU boots in <200ms to DISARMED. Pi UART TX ignored until `SUPERVISOR_HELLO + CRC` + 2s stable.
- Pi boot ~36s Armbian → melt-link starts at ~38s. Rotini LED = solid red until supervisor handshake, then blink. No motion difference.
- GPIO interlock: Pi GPIO reads ARM line (opto-isolated). If ARM high during Pi boot, Pi holds all TX until link re-armed. Prevents stale trim replay.
- Watchdog: `melt-link` heartbeat 10Hz to MCU. MCU requires 2Hz minimum else supervisor marked OFFLINE (no fault — just RC-only mode).
- Brownout: if Pi BEC sags, Pi may reboot mid-match — MCU continues. No reconnect transient: trims ramp 2s on rejoin.
- Bench test: pull Pi power mid-spin (tethered) → must show zero translation glitch. Log gap only.

## Fail Modes Tested
- SD ejection / RO remount → logging stops, control unaffected.
- UART short to GND → MCU timeout → RC-only.
- BEC failure → Pi dark → RC-only.
- WiFi on in pit only. Never in arena cage.
